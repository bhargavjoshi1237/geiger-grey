# Generation and transformation outputs built from a knowledge base

Scope: artifacts a product generates from ingested sources (documents, audio, video, web pages, notes), as opposed to chat turns. State of market as of October 2026. Method note: the session's shared web-search budget ran out partway through. The later sections (drafting tools such as Ironclad, Qorus, Copy.ai and Jasper; localization; SEO/FAQ pages; Swimm; Grain; Gamma; Hebbia funding) therefore rest on fewer sources, and the remaining holes are listed under each section's Gaps.

## 1. NotebookLM / Gemini Notebook "Studio" outputs, which are used most, and who copied them

### Takeaway
Google's notebook product (renamed from NotebookLM to Gemini Notebook on 16 July 2026) has grown into a menu of more than 10 one-click artifact types built from user sources. They include audio and video overviews, reports (briefing doc, study guide, blog post, custom), mind maps, flashcards, quizzes, slide decks, infographics, data tables, interactive learning overviews and, since June 2026, code-generated charts, spreadsheets and documents in many export formats. Audio Overviews are the only output with official growth evidence: daily creation doubled within two weeks of the 80+ language launch. Every other "most used" claim is anecdotal or comes from unreliable aggregators. Microsoft (Copilot Notebooks), ElevenLabs (GenFM) and open-source projects (Open Notebook, Podcastfy, NotebookLlama) copied the audio-overview pattern. Few competitors copy the full Studio menu.

### Cited Findings

- Google renamed NotebookLM to "Gemini Notebook" on 16 July 2026. Notebooks and features carried over — [Wikipedia, citing The Verge](https://en.wikipedia.org/wiki/NotebookLM); [Rutgers IT, "Same tool, new name"](https://it.rutgers.edu/2026/09/10/same-tool-new-name-notebooklm-is-now-gemini-notebook/). Third-party guides say notebooklm.google.com now redirects to notebook.google.com — [Kortex blog](https://www.kortex-notebooklm.com/blog/notebooklm-renamed-gemini-notebook) (secondary, unverified).

**Triggering, customization, grounding**
- The trigger is a Studio tile button. A pencil icon opens per-artifact customization (format, style, length, language, free-text focus instructions), and generation runs asynchronously while the user keeps working — [Google, Video Overviews](https://blog.google/innovation-and-ai/models-and-research/google-labs/video-overviews-nano-banana/). Since Mar 2026 an artifact can also be requested from chat — [Workspace Updates](https://workspaceupdates.googleblog.com/2026/03/new-ways-to-customize-and-interact-with-your-content-in-NotebookLM.html).
- Grounding is enforced by source selection: the user picks which sources feed an artifact, and Google says "all sources remain clearly attributed" — [Google, Jun 2026](https://blog.google/innovation-and-ai/products/notebooklm/better-research-notebooklm/). Flashcard and quiz explanations carry citations — [9to5Google](https://9to5google.com/2025/09/08/notebooklm-flashcards-quizzes/). The Data Tables post does not say whether cells are cited — [Google](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-data-tables/).
- Legal risk around synthetic voices: on 15 Feb 2026 journalist David Greene sued Google, alleging the podcast feature reproduced his voice. Google denies it — [Wikipedia → Washington Post](https://en.wikipedia.org/wiki/NotebookLM).

**API / programmatic access**
- NotebookLM Enterprise exposes `notebooks.audioOverviews.create` (v1alpha). It takes source IDs, an episode focus and a language code, allows one audio overview per notebook, and takes a few minutes — [Google Cloud docs](https://docs.cloud.google.com/gemini/enterprise/notebooklm-enterprise/docs/api-audio-overview).
- The standalone **Podcast API** (POST `discoveryengine.googleapis.com/v1/.../podcasts`) accepts up to 100k tokens of text or inline media, SHORT (~4–5 min) or STANDARD (~10 min) length, a focus prompt and a language, and returns an MP3 via a long-running operation. It is **deprecated: "Google isn't allowlisting new customers"** — [Google Cloud docs](https://docs.cloud.google.com/gemini/enterprise/notebooklm-enterprise/docs/podcast-api).
- A third-party guide states there is still no public consumer API — [Glasp](https://glasp.co/articles/notebooklm-2026) (secondary).

**Open-source / bring-your-own-model equivalents**
- **Open Notebook** (MIT, ~40.4k GitHub stars): a self-hosted NotebookLM alternative. It supports 20+ LLM providers, separate embedding providers, STT providers (OpenAI, Groq, Deepgram, ElevenLabs and others) and TTS providers (OpenAI, Google, ElevenLabs, Deepgram, Azure, Mistral, xAI, MiniMax, OpenAI-compatible and others). Podcasts can have 1–4 speakers with custom profiles, plus "Episode Profiles". "Transformations" are custom prompt-based outputs run over sources. Answers carry citations, and there is a REST API — [GitHub](https://github.com/lfnovo/open-notebook).
- **Podcastfy** (Apache 2.0) converts multimodal content into multilingual podcasts using OpenAI, Anthropic or Google LLMs and ElevenLabs or Google TTS — [Mozilla.ai blueprints](https://blueprints.mozilla.ai/resources/dont-want-to-build-from-scratch). **Meta NotebookLlama** is Llama-based, and its voices are criticized as unnatural with artifacts — [heise](https://heise.de/-9999224). **Open NotebookLM** (Hugging Face, 2024) is a fixed Llama 3.1 + MeloTTS pipeline — [It's FOSS](https://itsfoss.com/open-notebooklm/).

**BYO TTS feasibility (the key proprietary dependency)**
- ElevenLabs **Text to Dialogue** API places no limit on speakers per dialogue, sets a `voice_id` per turn, supports audio tags like `[laughs]` and runs on Eleven v4 (90+ languages) and v3 (70+). Requests are capped at ≤2,000 characters of total text, so long scripts must be chunked and concatenated. It explicitly targets podcasts. Commercial use requires a paid plan — [ElevenLabs docs](https://elevenlabs.io/docs/capabilities/text-to-dialogue).
- Gemini API native TTS: the page lists Gemini 3.8 Flash TTS (130+ languages) and Flash-Lite TTS (100+), plus older previews. Multi-speaker is limited to **2 speakers per request** with prebuilt voices. There are 30 prebuilt voices plus an extended library and custom voice design or replication. It names podcast generation as a use case — [Gemini API docs](https://ai.google.dev/gemini-api/docs/speech-generation).

### Inferences
- The Studio pattern breaks into three cost tiers for a BYO stack. (a) Text-only artifacts — briefing doc, study guide, FAQ, blog post, report, quiz, flashcards, data table, timeline — need only the user's LLM, a structured-output schema and citations. They are cheap to ship and easy to ground. (b) Structure artifacts — mind map, timeline, entity table — can be built largely from Grey's existing knowledge graph (entities, relations, dated events), with the LLM used only for labeling and summarizing. This is an advantage a RAG-only product lacks. (c) Media artifacts — audio overview, video overview, slides, infographics — need extra BYO adapters (TTS, optionally image generation) and renderers.
- Audio overview is the best-proven Studio artifact and is fully reproducible with BYO providers. The workflow is LLM script (with per-line source IDs) → TTS (ElevenLabs dialogue, Gemini 2-speaker, or per-turn single-voice TTS stitched together) → MP3 plus transcript with citations. Google's own Podcast API is deprecated, so a provider-neutral "podcast from sources" endpoint is a gap Grey could fill.
- Video overviews, slide decks and infographics depend on Google's proprietary image models (Nano Banana / Nano Banana Pro) for their look. A BYO version should default to deterministic templates (HTML/PPTX layouts filled with LLM-written content and KG diagrams) and treat a user-attached image model as optional. That avoids a hard dependency on any one image model.
- The "chat-to-artifact" bridge (Mar 2026) suggests artifacts should also be callable from Grey's chat, MCP server and OpenAI-compatible endpoint, not only from a Studio button.
- Microsoft's roadmap adding Critique and Debate formats and topic-based episodes indicates the audio pattern is converging on a set of "format presets" (deep dive, brief, critique, debate). Each preset is just a prompt template, and any LLM can implement it.
- The Greene lawsuit suggests a BYO model, where users pick their own voices, moves voice-likeness risk off Grey. Grey should still avoid shipping cloned or celebrity-like default voices.

### Gaps
- Google has published no per-feature usage share (Audio vs Mind Map vs Reports vs Flashcards). All percentages found are from unreliable aggregators.
- I could not verify whether the 2024 "FAQ", "Timeline" and "Table of contents" Notebook Guide buttons still exist in 2026 or were folded into Reports and "Create Your Own". 2025 sources list only Briefing Doc, Study Guide, Blog Post and custom.
- The model behind Cinematic Video Overviews (e.g. whether Veo is used) and the exact TTS model behind Audio Overviews are not stated in the sources found.
- A reported 2 Sep 2026 change to compute-based usage limits came only from blogs and was not verified.
- Microsoft 365 Copilot license price and Copilot Notebooks "Pages" features were not researched (search budget exhausted).
- Audio-overview formats in NotebookLM itself (Deep Dive / Brief / Critique / Debate) were not confirmed from a primary source in this session.

## 2. Auto-generated wikis and documentation from sources, and how they stay fresh

### Takeaway
"Compile the sources into a wiki" is now a recognized pattern. It runs from code (DeepWiki, Mintlify) to company knowledge (Zendesk Knowledge Builder, Rovo KB-from-ticket) to personal research (Karpathy's "LLM wiki", April 2026). Freshness is handled in three ways. Event-triggered regeneration on diff or merge (Mintlify) is the most mature. Human verification cadences (Guru) are the second, and manual regeneration (DeepWiki) the third, which users complain goes stale. Generated pages are almost always staged as drafts or PRs for human review.

### Cited Findings
- **DeepWiki (Cognition/Devin).** It indexes repos and produces wiki pages with architecture diagrams, "links to sources" (code) and codebase summaries. The wiki is auto-generated when repos are connected, and it also serves as context for "Ask Devin". A `.devin/wiki.json` file (repo_notes plus an explicit page list with title, purpose, parent and page_notes) replaces automatic cluster-based page planning. Limits: 30 pages (80 enterprise), 100 notes, 10k characters per note. Effort tiers: Low is free, Medium ~5–10 ACUs per wiki, High ~20–40 ACUs. A free public version runs at deepwiki.com, with a DeepWiki MCP server. **Refresh: the docs describe only manual regeneration** after committing wiki.json — [Devin docs](https://docs.devin.ai/work-with-devin/deepwiki).
- An OpenWrt maintainer reported that a DeepWiki page "does not get regenerated if the repo is updated and it cannot be removed" and warned it contained inaccuracies — [OpenWrt forum](https://forum.openwrt.org/t/important-consideration-deepwiki-ai-generated-docs-may-contain-inaccuracies/249471). This is a secondhand complaint.
- RAGFlow has **no native wiki generator**. Its "DeepWiki" page points to the DeepWiki-generated wiki of the RAGFlow codebase, which DeepWiki maintains — [RAGFlow docs](https://ragflow.io/docs/deepwiki). Its 2026 releases added ingestion pipeline templates, agent publishing, sandboxed code execution and chart generation — [knightli notes](https://knightli.com/en/2026/04/15/ragflow-rag-engine-guide/) (third-party).
- **Mintlify "automations/workflows"** (blog dated 3 Apr 2026). Triggers: push or merge to main (the agent reads the diff, finds affected pages and updates them), releases (changelog generation from merged PRs), weekly schedules (audits for broken links, outdated examples and deprecated-feature references) and new-feature PRs (first-draft pages). The agent clones the relevant repos, follows a user-defined prompt, then **opens a PR or pushes directly** — [Mintlify blog](https://www.mintlify.com/blog/docs-on-autopilot). The agent "cites where the changes come from in your source code repositories" — [Mintlify use cases](https://www.mintlify.com/blog/automations-usecases). A DIY route calls Mintlify's agent API from GitHub Actions or n8n — [Mintlify guide](https://www.mintlify.com/docs/guides/automate-agent).
- **Guru.** Freshness is modeled as *verification*. Every card has a named verifier and a verification or expiry date, and the Knowledge Agent can auto-verify or unverify content based on usage patterns and feedback signals. Configuring this needs the Knowledge Agent Owner role — [Guru help](https://help.getguru.com/docs/verifying-and-unverifying-cards); [Guru 201](https://help.getguru.com/docs/guru-201). I found no source on Guru auto-*generating* cards.
- **Atlassian Rovo.** A `manage-knowledge-base` skill turns resolved Jira Service Management tickets into Confluence KB article drafts ("Create KB from issue KEY-123"), drawing on similar closed issues, for admin review — [release-note mirror](https://jimiwikman.se/atlassian/atlassian-resources/atlassian-app-updates/rovo-create-knowledge-base-articles-with-ai-in-jira-service-management-r844/); [Atlassian use case](https://www.atlassian.com/software/rovo/use-cases/draft-and-update-knowledge-base-articles). Rovo pulls context from linked Jira issues and Confluence pages when drafting project plans — [Atlassian blog](https://www.atlassian.com/blog/rovo/create-and-edit-with-rovo). Bug ROVO-613, "Generating a Confluence Page From Rovo Hangs", was open — [Atlassian Jira](https://jira.atlassian.com/browse/ROVO-613).
- **Zendesk Knowledge Builder** (GA 20 Nov 2025, all plans with Knowledge). It analyzes 90 days of solved tickets, clusters common issues, combines them with brand and audience context (and the website), and generates a **whole new help center**. The preview proposes up to 40 articles, with up to 10 regenerations, and creates drafts for review. It works in any selected language, allows one help center per brand, does not improve an existing well-maintained help center and may create duplicate sections — [Zendesk announcement](https://support.zendesk.com/hc/en-us/articles/9966092609050-Announcing-the-general-availability-of-the-Knowledge-builder); [Zendesk blog](https://www.zendesk.com/blog/zendesk-insights/innovation/fuel-your-ai-with-a-knowledge-base-built-in-days-not-months/). Drafts are labeled "AI-generated", and the early-access version produced 20–25 drafts — [Zendesk blog](https://www.zendesk.com/blog/zendesk-insights/innovation/fuel-your-ai-with-a-knowledge-base-built-in-days-not-months/).
- **Glean Canvas.** A co-authoring surface opened automatically when Glean detects writing intent in chat (e.g. "weekly report"). It drafts documents, emails and presentations grounded in company knowledge, with a **Sources section whose citations link to the original documents**, section-level refinement and version history. It exports to Gmail/Google Docs or Outlook/Word once admin actions are configured, and to slides, spreadsheets or interactive artifacts — [Glean docs](https://docs.glean.com/user-guide/assistant/glean-chat/canvas). The June 2026 release added in-document comments with "Apply All" revision and voice document creation — [Glean release notes](https://docs.glean.com/release-notes/releases/2026-06-17-june-release). The Nov 2025 launch was single-author, not real-time collaborative — [Glean release notes](https://docs.glean.com/release-notes/releases/2025-11-19-november-release).
- **Notion.** No dedicated "auto-wiki" generator was found. The closest native features are AI Autofill and Custom Agents (Section 5) — [Notion help](https://www.notion.com/help/autofill).
- **Karpathy "LLM knowledge base / LLM wiki" pattern** (early Apr 2026, secondary write-ups). There are three layers: immutable `raw/` sources, an LLM-maintained Markdown wiki (summaries, entity and concept pages, backlinks) and a schema file (CLAUDE.md/AGENTS.md) with conventions. Operations are *ingest* (integrate new sources, update existing pages, flag contradictions), *query* and *lint* (check inconsistencies). One example wiki is ~100 articles and ~400k words — [Denser](https://denser.ai/blog/llm-wiki-karpathy-knowledge-base/); [Pebblous](https://blog.pebblous.ai/report/karpathy-llm-wiki/en/); [Daniel Vaughan](https://codex.danielvaughan.com/2026/04/11/karpathy-llm-knowledge-bases-codex-resources-flywheel/). No primary Karpathy post was retrieved.

### Inferences
- Grey's knowledge graph maps directly onto the "LLM wiki" layout. One page per entity (or per community/cluster) combines the entity's relations, the source chunks that mention it and an LLM-written summary with citations. Backlinks are free from relations. This makes "Project Wiki" a natural first-class Grey artifact.
- Freshness should be dependency-tracked. Each generated page or section stores the source and chunk IDs (and versions) it used. On re-ingest or source change, affected pages are marked stale and either regenerated automatically (Mintlify-style, on a "source changed" event) or queued for review (Guru/Zendesk-style). A scheduled "lint" job can detect contradictions between pages and new sources.
- Every vendor stages output as drafts or PRs. Grey should version generated artifacts, show a diff between regenerations and support an approval state before anything is published to the hosted widget or the API.
- Zendesk's "generate a help center from tickets" shows the high-value enterprise variant is clustering *demand* (questions asked) and writing articles to cover it. Grey has the data for this if it logs chat and retrieval queries.

## 4. Media-specific outputs from audio and video (transcripts, chapters, clips, show notes, summaries, moments, captions)

## 8. Q&A pair and FAQ generation (support deflection, SEO) and synthetic evaluation datasets

### Takeaway
Q&A and FAQ generation appears in two commercially proven forms. Support platforms mine conversations to propose new articles or snippets for content gaps (Intercom Fin, Zendesk Knowledge Builder, Atlassian Rovo). Developer tools generate synthetic Q&A test sets from the corpus to evaluate RAG (Ragas builds a knowledge graph of documents first, then synthesizes single-hop and multi-hop queries). Video APIs (Twelve Labs) emit Q&A pairs per video. Grey's own KG and query logs make both directions feasible: *corpus → questions* for FAQs and evals, and *unanswered queries → articles* for gap-filling.

### Cited Findings
- **Intercom "Content from conversations"** (beta). Each time a conversation closes, Fin checks for a knowledge gap and drafts a new snippet only if a gap exists and there is enough information to fill it. Suggestions queue in Fin AI Agent → Train → Suggestions, with a cap on pending items, and expire if not reviewed (4 weeks per one help page, 2 weeks per another) — [Intercom help](https://www.intercom.com/help/en/articles/10260362-content-from-conversations-beta); [Fin help](https://fin.ai/help/en/articles/10727368-content-from-conversations). The newer **AI-powered content suggestions** analyze conversations Fin could not resolve and propose new content or edits to existing content. They flag duplicate or conflicting articles, exclude conversations without teammate replies, abandoned chats and bug or feature requests, skip content already covered, and can be segmented by audience — [Intercom help](https://www.intercom.com/help/en/articles/11394959-use-ai-powered-content-suggestions-to-improve-fin); [CreateWith](https://www.createwith.com/tool/intercom/updates/intercom-ships-january-fin-updates-with-automation-rate-tracking-and-ai-powered-). A third-party account says suggestions are ranked by likely impact by comparing failed Fin chats with successful human replies — [eesel](https://www.eesel.ai/blog/fin-ai-suggestions).
- **Zendesk Knowledge Builder**: ticket clusters → help-center article drafts (Section 2) — [Zendesk](https://support.zendesk.com/hc/en-us/articles/9966092609050-Announcing-the-general-availability-of-the-Knowledge-builder).
- **Rovo**: resolved tickets → KB article drafts — [Atlassian](https://www.atlassian.com/software/rovo/use-cases/draft-and-update-knowledge-base-articles).
- **Twelve Labs Pegasus** outputs "Q&A pairs" from video — [Twelve Labs](https://www.twelvelabs.io/llms-full.txt).
- **Ragas test-set generation.** Wraps documents as nodes in a `KnowledgeGraph`, applies transforms (headline extraction and splitting, etc.) with the user's chosen LLM and embedding model, then uses query synthesizers (single-hop specific, multi-hop abstract, multi-hop specific) and personas to produce question, ground-truth and context samples — [Ragas docs](https://docs.ragas.io/en/stable/howtos/applications/singlehop_testset_gen/); [Ragas v0.2.7 docs](https://docs.ragas.io/en/v0.2.7/getstarted/rag_testset_generation/); [QASkills guide](https://qaskills.sh/blog/rag-synthetic-testset-generation-ragas-guide-2026). Caveats: generated rows are not ground truth by default and need validation, leakage checks and held-out splits — [QASkills](https://qaskills.sh/blog/rag-synthetic-testset-generation-ragas-guide-2026). A 2026 ESG-domain paper notes **self-enhancement bias** when the generator model is also among the evaluated models — [arXiv 2609.15242](https://arxiv.org/pdf/2609.15242).
- NotebookLM's quizzes are themselves Q&A generation with citations — [9to5Google](https://9to5google.com/2025/09/08/notebooklm-flashcards-quizzes/).

### Inferences
- Grey can generate an **evaluation dataset per pipeline** with the user's own LLM, Ragas-style. It would sample KG neighborhoods for multi-hop questions and single chunks for single-hop, store question, expected answer and gold chunk IDs, then score the pipeline's /retrieve and chat endpoints for recall@k and answer faithfulness. This doubles as a product feature ("pipeline health score") and as protection against regressions when users change chunking or embedding settings. Use a different BYO model for generating and judging where possible, given the self-enhancement-bias finding.
- FAQ generation for deflection and SEO is the same machinery pointed outward. Generate a candidate question set, answer each with citations, deduplicate against existing content, and publish as an FAQ page or JSON-LD FAQ schema, or as "suggested questions" in the hosted chat widget.
- Gap detection (Intercom/Zendesk style) needs Grey to log questions where retrieval confidence was low or users gave negative feedback, then cluster them and draft articles to cover them. This turns the existing chat surfaces into a source of generation jobs.

### Gaps
- No vendor data on deflection rates attributable specifically to auto-generated articles was found.
- SEO-oriented FAQ generators and Google's 2026 treatment of FAQ rich results were not researched (search budget).
- Synthetic-data products beyond Ragas (e.g. Giskard, Patronus, Vertex or Bedrock evaluation dataset generation) were not researched.

## 9. Cross-pattern synthesis: most proven patterns, and what each needs on top of Grey's RAG + KG stack with BYO models

### Takeaway
Ranked by commercial proof and demand evidence gathered above:
1. Audio overview/podcast from sources (NotebookLM, Microsoft, ElevenLabs, open source).
2. Grounded templated drafting (RFP/proposal/brief/report: Loopio, Responsive, Spellbook, Writer, Gong, Glean).
3. Help-center and KB article generation from tickets and conversations (Zendesk, Intercom, Rovo).
4. Media derivatives (show notes, chapters, clips: Descript, Riverside, Fireflies, Castmagic, Twelve Labs).
5. Study/learning sets (flashcards, quizzes, courses: NotebookLM, Articulate, Recall).
6. Auto-wiki with change-triggered refresh (DeepWiki, Mintlify, LLM-wiki pattern).
7. Scheduled digests and briefings (Slack Recaps, Pulse, Feedly, Notion, Writer).
8. Structured extraction tables or matrices (NotebookLM Data Tables, Hebbia).

All but avatar video and Google-style illustrated video or slides can be built with any user-attached LLM, plus a user-attached TTS for audio.

### Cited Findings
- Audio is the only Studio output with official growth evidence (daily creation doubled after the language expansion) — [Google](https://blog.google/technology/ai/developing-notebooklm/). Microsoft is extending its copy with Critique and Debate formats in Oct 2026 — [M365 roadmap](https://mc.merill.net/message/RM570966). Google's standalone Podcast API is deprecated for new customers — [Google Cloud](https://docs.cloud.google.com/gemini/enterprise/notebooklm-enterprise/docs/podcast-api).
- RFP drafting carries five-figure annual contracts (Loopio median ~$23.7k per year per Vendr) — [KI-Syndikat](https://www.ki-syndikat.de/tools/loopio/).
- Help-center generation is GA on all Zendesk Knowledge plans — [Zendesk](https://support.zendesk.com/hc/en-us/articles/9966092609050-Announcing-the-general-availability-of-the-Knowledge-builder).
- Per-minute pricing exists for video derivative APIs ($0.0292 per minute plus tokens) — [Twelve Labs](https://www.twelvelabs.io/llms-full.txt).
- Google's own artifact export formats as of Jun 2026 (PDF, DOCX, MD, CSV, JSON, XLSX, PPTX, PNG, SVG) are a reference list for renderers — [Google](https://blog.google/innovation-and-ai/products/notebooklm/better-research-notebooklm/).
- Proprietary dependencies observed: Nano Banana / Nano Banana Pro for NotebookLM video, slides and infographics — [Google](https://blog.google/innovation-and-ai/models-and-research/google-labs/video-overviews-nano-banana/); [Wikipedia → XDA](https://en.wikipedia.org/wiki/NotebookLM). Avatar presenters in Synthesia — [Synthesia](https://www.synthesia.io/tools/pdf-to-video). Multi-speaker TTS limits differ by provider (ElevenLabs dialogue has no speaker limit but caps text at 2,000 characters per request; Gemini allows 2 speakers per request) — [ElevenLabs](https://elevenlabs.io/docs/capabilities/text-to-dialogue); [Gemini API](https://ai.google.dev/gemini-api/docs/speech-generation).
- BYO feasibility proof: Open Notebook already ships podcast generation and prompt-based "transformations" across 20+ LLM and 12+ TTS providers under MIT — [GitHub](https://github.com/lfnovo/open-notebook).

### Inferences
**Pattern → BYO feasibility → what Grey needs beyond RAG + KG**

| Pattern | BYO-only feasible? | Proprietary dependency | Grey additions needed |
|---|---|---|---|
| Text reports (briefing, study guide, blog post, custom) | Yes, any LLM | None | Artifact type registry (prompt + JSON schema + renderer), async job runner, per-paragraph citations to chunk IDs, MD/DOCX/PDF export |
| Templated drafting / RFP fill | Yes | None | Template/section model, per-section scoped retrieval, batch "question list → cited answers" job over existing /retrieve, approved-answer library source type, review/approve state |
| Data table / matrix | Yes | None | Schema-from-prompt, per-cell extraction with citations, CSV/XLSX export; can reuse KG entity attributes |
| Mind map / concept map | Yes, mostly deterministic | None | Render KG subgraph (entities + relations) to Mermaid/JSON; LLM only for cluster labels |
| Timeline | Yes | None | Date normalization of extracted events/relations in KG; ordered render with citations |
| Auto-wiki (entity pages) | Yes | None | Page-per-entity/cluster generator, backlinks from relations, dependency tracking (artifact ↔ source versions), stale flags, regenerate-on-change trigger, diff view |
| Flashcards / quizzes / course outline | Yes | None | Item schema with source chunk IDs, difficulty/count params, invalidation on source change; optional SCORM/CSV/Anki export |
| Audio overview / podcast | Yes, with BYO TTS | Voice quality depends on chosen TTS; Gemini limits to 2 speakers per request; ElevenLabs needs chunking | Script generator with format presets (deep dive, brief, critique, debate), TTS adapter interface, audio stitching worker (ffmpeg), storage, transcript with citations, API endpoint (fills gap left by deprecated Google Podcast API) |
| Video overview / slides / infographics | Partially | Google uses Nano Banana / Pro for visuals | Deterministic slide/infographic templates (HTML→PDF/PPTX), optional BYO image-model adapter, TTS narration + video render worker |
| Media derivatives (chapters, show notes, moments, captions) | Yes, BYO STT + LLM | None (visual-moment detection needs a video-capable model) | Timestamped transcript segments as chunks, auto-on-ingest derivative jobs, citation format with start/end ms, optional clip cutting worker |
| Scheduled digests / "what changed" | Yes | None | Per-project scheduler, "since last run" watermark over sources and KG changes, delivery adapters (email/Slack/webhook — possibly the suite's notify package), issue archive, token-cost estimate |
| Help-center / FAQ from gaps | Yes | None | Logging of low-confidence or negatively rated queries, clustering, article drafting with citations, dedupe against existing content, publish to widget/FAQ schema |
| Synthetic eval sets | Yes | None (prefer a different model for generation vs judging) | Ragas-style KG-driven question synthesis, gold chunk IDs, scoring harness against pipeline endpoints |

- **Shared platform pieces** recur across all patterns: (1) an artifact object (type, params, source scope, model config, status, version, citations); (2) a durable async job runner for multi-minute generations; (3) renderers and exporters; (4) source-dependency tracking for staleness; (5) triggers: button or template in the UI, chat-to-artifact, API/MCP tool, on-ingest, schedule, source-changed event; (6) review/approval before publishing. Building these once lets each new output type be "just a template".
- **Grounding pattern to copy.** Every serious vendor attaches citations at the smallest practical unit: Glean's Sources section, NotebookLM's citation-backed Explain on quiz items, Mintlify's code citations, Writer's sources at the bottom. Grey should require structured output where each sentence, cell, quiz item or script line carries chunk IDs. Unsupported claims are flagged rather than silently emitted.
- **Where the KG is a differentiator.** Mind maps, timelines, entity wikis, "what changed" digests and multi-hop eval questions all get better or cheaper with a KG. These are the outputs a RAG-only competitor does worst. They are the strongest candidates for Grey's distinct "beyond chat" story within the Geiger suite.
- **Suggested sequencing (inference only):** (1) text reports, data tables and flashcards/quizzes, which are cheap, citation-friendly and reuse the existing pipeline config; (2) KG mind map and timeline; (3) auto-wiki with staleness; (4) audio overview via BYO TTS; (5) scheduled digests; (6) RFP/question-list batch fill; (7) eval-set generation; (8) slides and video.

### Gaps
- No cross-vendor usage data ranks these patterns by actual end-user frequency. The ranking above combines official growth signals, pricing and availability, so it is an inference.
- Gamma (document → deck), whose pricing page returned HTTP 403, and Hebbia funding and pricing could not be verified, so the slide and matrix categories lack commercial numbers.
- The BYO costs of audio and video generation per minute were not modeled. Provider TTS prices were not retrieved.
