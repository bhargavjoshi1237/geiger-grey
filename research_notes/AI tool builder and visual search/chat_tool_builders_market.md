# Market and product landscape: "describe a tool in chat, get a working tool" (as of October 2026)

Research note scope: who ships chat-to-tool builders, how each works, whether the built tool can use the user's own data, how it is shared, pricing, demand and failure signals, and where a vector- and knowledge-graph-grounded builder inside Geiger Grey would sit. Method note: WebSearch hit its session budget partway through; the rest of the research used direct fetches of vendor docs, pricing pages and changelogs, plus the Hacker News Algolia API. openai.com and help.openai.com returned HTTP 403 to direct fetches, so some OpenAI facts rest on search snippets of OpenAI pages or on secondary sources. Those are flagged.

## 1. Who ships natural-language mini-app and tool builders, what do they generate, and which are grounded in the user's own data?

### Takeaway
The space is crowded but turning over fast. In the second half of 2026 the first-generation consumer builders are being shut down or folded into "skills" and "plugins": Google Opal (Nov 17, 2026), Gemini Gems (from Nov 2026), custom GPTs (reported, Dec 2026), OpenAI Agent Builder (Nov 30, 2026), Microsoft's App Builder agent and vibe.powerapps.com (Nov 30, 2026), Flowise (Aug 31, 2026) and hosted DataStax Langflow (Apr 9, 2026). What survives and grows falls into three groups: generated-code app builders (Lovable, Bolt, v0, Replit, Retool AppGen, Copilot Studio apps, GlideOS, Claude artifacts); agent builders inside a workspace that hold the customer's data (Notion Custom Agents, Glean, Dust, Airtable Omni, Copilot Studio); and workflow and agent builders for automation (Gumloop, Lindy, Zapier, Relevance AI, MindStudio, Dify, Stack AI, Pickaxe). Products grounded in the user's data are mostly the workspace-native ones, where the vendor already holds that data. Generic app builders reach data only through connectors or a generated database. Almost every hosted builder resells vendor models through credits. Customer-key (BYO) support is the exception: Dify after its included credits, MindStudio, Elastic, Glean's model hub, and Glide Enterprise.

**Consumer and assistant-native builders**
- **Google Opal (Labs; shutting down Nov 17, 2026).** Users describe an app's logic in natural language, and Opal builds a visual multi-step workflow that chains prompts, model calls and tools. The workflow can be refined by conversation or in a visual editor, and is shared so others can run it "with their own Google account". It launched July 24, 2025 as a US-only beta — [Google Developers Blog](https://developers.googleblog.com/en/introducing-opal/). It expanded to 15 more countries on Oct 7, 2025 and added step-by-step debugging and parallel runs — [Google blog](https://blog.google/technology/google-labs/opal-expansion/). An "agent" step (Feb 24, 2026) added memory across sessions, plain-language routing between paths, and interactive follow-up questions. Its examples include a Room Styler that takes an uploaded room photo — [Google blog](https://blog.google/innovation-and-ai/models-and-research/google-labs/opal-agent/). The agent step is reported as running on Gemini 3 Flash — [OODA Loop](https://oodaloop.com/briefs/technology/google-adds-ai-agent-to-opal-mini-app-builder/). Opal was brought into Gemini's Gems manager as "Gems from Labs" (Dec 17, 2025), where a Workflow Builder generates steps, system prompts and visual elements from a description, and apps can be published by public link — [TestingCatalog](https://www.testingcatalog.com/google-started-rolling-out-super-gems-from-opal-inside-gemini.md). Opals are private by default and can be shared with editor view and remix toggles. Sharing exposes the underlying Drive file — [Opal FAQ](https://developers.google.com/opal/faq). Models are Google's only. No source shows grounding in a user corpus beyond inputs and Drive storage.
- **Gemini Canvas.** Generates code for apps, games, quizzes, web pages and infographics, shareable by link, for all Gemini users. The page does not say whether generated apps can call Gemini or read user data — [Gemini Canvas](https://gemini.google/overview/canvas/)
- **Claude Artifacts.** Artifacts can call Claude ("AI-powered artifacts") with no API keys. "Usage counts against each person's own plan limits rather than yours", so sharing costs the builder nothing. Persistent storage (Pro, Max, Team, Enterprise) comes in personal or shared modes, is limited to 20 MB per artifact, and is text only (no images or binary). Artifacts can read and write connected apps and custom connectors after per-tool approval, and "everyone connects their own apps, even for shared or published artifacts". Templates (Docs, Slides, Design) and Dashboards (beta) exist. Legacy artifacts lose their storage when unpublished — [Claude Help Center](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them). Vendor models only. Grounding comes from the user's own connectors, not a vendor-held corpus.
- **ChatGPT custom GPTs.** Instructions plus knowledge files plus Actions defined by an OpenAPI schema — [Jotform](https://www.jotform.com/ai/what-is-a-custom-gpt/). Reported as being retired (see above). OpenAI models only.
- **ChatGPT Apps SDK / App Directory / Plugins.** The App Directory launched in December 2025, built on the Apps SDK and MCP. Early listings included Spotify, Canva, Booking.com, Instacart and Zillow. Selling digital goods was initially not allowed — [Moburst](https://www.moburst.com/blog/chatgpt-app-directory-explained-what-brands-need-to-know/); [VentureBeat](https://venturebeat.com/technology/openai-now-accepting-chatgpt-app-submissions-from-third-party-devs-launches). The current docs list a Checkout API for plugin UIs — [OpenAI developer docs](https://developers.openai.com/apps-sdk). Apps and plugins are built by developers, not generated by end users in chat.
- **ChatGPT Workspace Agents** (announced Apr 22, 2026; 161 points and 64 comments on HN). These are shared team agents that work asynchronously on files and messages, can be tagged in Slack, and keep a memory file store. They are a research preview on Business, Enterprise, Edu and Teachers plans — [OpenAI](https://openai.com/index/introducing-workspace-agents-in-chatgpt/) (via [HN thread](https://news.ycombinator.com/item?id=47866860); the OpenAI page itself returned 403)

### Inferences
- Persona-and-prompt builders (GPTs, Gems) and rigid node-graph builders (Opal, OpenAI Agent Builder, Flowise, Power Apps Vibe) are what is being retired. What replaces them is either a **skill** (instructions plus files, invoked inside a general agent; Gemini skills, Dust skills, OpenAI plugins) or **generated code with a live preview and data connections** (Copilot Studio apps, Claude artifacts, GlideOS, Lovable, Retool). A Grey tool builder should match one of these two shapes. A third bespoke canvas would go against the trend.
- Grounded builders are almost all "the vendor already owns the data": Notion over pages and databases, Airtable over bases, Glean and Dust over connected company sources, Copilot Studio over Dataverse, SharePoint and Graph, Glide over spreadsheets, Elastic over indexes. Generic app builders such as Lovable, Bolt, v0, Replit and Canvas generate a fresh database or rely on connectors the user wires up. Grey owns the data, which places it in the first group.
- Assistant-native builders (Claude artifacts, ChatGPT plugins, Gemini skills) consume external data through MCP or connectors. Grey already has an MCP server, so Grey-grounded tools can show up inside those assistants without Grey building their UI.
- BYO-key support is rare among hosted builders. Grey's BYO-only stance is a differentiator for cost-sensitive or regulated buyers, but it means Grey cannot offer the "it just works on free credits" first run that Notion, Airtable and Claude offer.

### Gaps
- I could not verify the custom GPT retirement against an OpenAI primary source (403). Treat the dates as unconfirmed.
- I found no official model or BYO details for Airtable Omni, Retool AppGen, Softr, Gumloop, Stack AI or Zapier Agents.
- No current pricing for Copilot Credits per app action, Zapier Agents, Gumloop or Softr was retrieved.
- The Dust "Sidekick" natural-language builder is unconfirmed.
- I found no adoption numbers for Claude artifacts, Opal, Copilot Studio apps or Pickaxe.

## 2. What kinds of tools do users actually build with these?

### Takeaway
The evidence points to routing, triage and qualification (classifiers in all but name), internal Q&A, reporting and digests, intake forms and trackers, and content generators. Most consumer-built assistants are thin prompt wrappers that see little use. Image-input tools appear mainly as generative toys (Opal Room Styler). I found no gallery that features retrieval-style "find similar items" or "classify against stored examples" tools as a first-class template.

### Cited Findings
- Notion Custom Agents' named use cases are ticket triage, internal Q&A, daily standups, status reporting and inbox management. Remote's IT agents triage tickets with over 95% accuracy, resolve more than 25% autonomously, and save about 20 hours a week — [Reworked](https://www.reworked.co/digital-workplace/notion-custom-agents-reach-general-availability/)
- Copilot Studio apps' intended scenarios are tracking work or inventory, collecting information, managing requests, reviewing business data, and dashboards for an individual or team — [Microsoft Learn FAQ](https://learn.microsoft.com/en-gb/microsoft-copilot-studio/faq-apps)
- Opal examples: Visual Storyteller, Room Styler (upload a room photo plus a style), Video Hooks Brainstormer (remembers brand identity) and Executive Briefing (routes new vs existing clients) — [Google blog](https://blog.google/innovation-and-ai/models-and-research/google-labs/opal-agent/). Google said US users built apps for business-process automation, marketing and creative projects, without naming any — [Google blog](https://blog.google/technology/google-labs/opal-expansion/). On HN, few commenters reported builds. One built a book recommender, and another said "each thing I tried could be handled better by a normal gem with custom prompt" — [HN thread](https://news.ycombinator.com/item?id=46441068)
- In a crawl of 334,348 custom GPTs, 45.62% had no category. The rest: Other 26.40%, Lifestyle 6.12%, Education 5.85%, Productivity 5.56%, Research 3.64%, Writing 2.94%, Programming 2.48%. Only 2.96% used Actions (external APIs), while 93.58% used browsing — [arXiv 2405.10547](https://arxiv.org/html/2405.10547v1)
- Relevance Invent's showcased agents are Lead Researcher, Inbound Qualifier and Outreach Writer (qualifier = classification) — [Relevance Invent](https://relevanceai.com/invent)
- Airtable's showcased field agents extract feature requests, pain points, competitor mentions and buying signals from call transcripts (extraction plus tagging) — [Airtable newsroom](https://airtable.com/newsroom/introducing-the-ai-native-airtable)
- Gumloop's example routes a contract PDF from a Drive folder to Salesforce and Slack — [DataCamp](https://www.datacamp.com/tutorial/gumloop-tutorial). Reviewers say Lindy's inbox triage, meeting scheduling and follow-ups work within minutes from templates — [Automation Atlas](https://automationatlas.io/answers/lindy-pricing-explained-2026/)
- Zapier Forms templates cover application, booking, order and contact intake — [Zapier Forms](https://zapier.com/interfaces)
- Image-input capability exists as a primitive in some builders but is not showcased as retrieval. Dify 1.17.0 sends image files to multimodal models in LLM nodes and agents and supports knowledge bases with images ("multimodal vectors") — [Dify releases](https://github.com/langgenius/dify/releases). Claude artifact storage is text only, with no images or binary — [Claude Help Center](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)

### Inferences
- "Classifier that picks from a fixed set" is a proven need, but buyers meet it as **triage, routing, qualification or tagging** inside a workflow, not as a standalone "classifier tool". Grey should name tool types by job (triage, tag, match, look up) and wire outputs into the suite (Flow issues, Forms).
- Calculators, form-to-answer tools and internal helpers dominate the generic app-builder showcases. Retrieval tools ("find the 5 most similar past cases or images", "which stored example does this resemble") are absent from the galleries I reviewed. They are either unserved or under-marketed, and only a builder that owns vectors can make them a one-click template.
- The long tail of custom GPTs (Lifestyle, Writing, persona bots, few Actions) shows that easy-to-make assistants with no data or actions are the first to be abandoned.

### Gaps
- I did not retrieve per-category counts from current template galleries (Notion agent templates, Zapier agent templates, MindStudio, Pickaxe). The Opal gallery is no longer reachable on its landing page.
- I found no quantitative evidence on how often image-input or similarity tools are built in any of these products.

## 3. Who builds and who uses, and what are the pricing models?

### Takeaway
Two populations. Admins and ops staff build for their own team inside a workspace product (Notion, Copilot Studio, Glean, Dust, Airtable, Glide, Retool, Lindy, Gumloop, Zapier), paying per seat plus a pooled credit meter. Creators and businesses build for their own customers through embeds, white-label portals or public links (Pickaxe, MindStudio, Dify, Stack AI, Lovable and other generated apps, Claude artifacts, GPTs, ChatGPT plugins). Pricing has converged on **plan fee plus vendor-billed AI credits**. Per-published-app limits (Glide), per-workspace annual fees (Dify), revenue share (Pickaxe) and "viewer pays from their own plan" (Claude) are the notable variants.

### Cited Findings
- Internal by default: Glide apps are "private to the company by default", with roles extending to managers, customers and partners — [Glide](https://www.glideapps.com/). Copilot Studio apps are shared "with selected people and groups" under org policy, and sharing does not grant data access — [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-copilot-studio/apps-experience/apps-overview). Notion agents are shared with people, groups or the whole workspace with Full, Can Edit and Can View & Interact levels. By default any workspace member can create agents, and Enterprise admins can restrict that — [Notion Help](https://www.notion.com/help/custom-agents)
- Building for customers: Pickaxe supports subscriptions, one-time payments and pay-per-use via Stripe, paywalled tools, embeds and white-labeling, with 90–98% revenue retained — [Pickaxe pricing](https://pickaxe.co/pricing); [Pickaxe](https://pickaxe.co/sell-your-ai). MindStudio agents embed on the customer's own site or are triggered by API or webhook — [MindStudio pricing](https://www.mindstudio.ai/pricing)
- Viewer-pays model: shared Claude artifacts bill AI usage to each viewer's own plan, and Team and Enterprise members use shared artifacts at no added cost to the builder — [Claude Help Center](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them). Opal apps also ran on each user's own Google account — [Google Developers Blog](https://developers.googleblog.com/en/introducing-opal/)
- Seat pricing: v0 Plus $30 and Business $100 per user per month — [v0 pricing](https://v0.app/pricing). Bolt Teams $27 per member per month — [Bolt pricing](https://bolt.new/pricing). Notion Custom Agents require a Business or Enterprise plan plus credits — [Notion Help](https://www.notion.com/help/custom-agents)
- Credit pools: Lovable prices on credits, not seats, with members sharing one pool — [Lovable pricing](https://lovable.dev/pricing). Lindy credits are pooled, with $10 per 1,000 top-ups — [Lindy pricing](https://www.lindy.ai/pricing). Copilot Studio apps consume Copilot Credits to build, preview and use — [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-copilot-studio/apps-experience/apps-overview). Notion's Select credits do not roll over, and running an agent through the API consumes Notion credits — [Notion pricing help](https://www.notion.com/help/custom-agent-pricing)
- Per-published-app limits: Glide Basic allows 2 published apps, Plus 5 (and public apps), Pro unlimited — [Glide pricing](https://www.glideapps.com/pricing). Softr claims unlimited published apps on all plans (vendor) — [Softr](https://v2.softr.io/blog/best-ai-no-code-app-builders)
- Per-workspace annual pricing: Dify Professional $590 per year and Team $1,590 per year — [Dify pricing](https://dify.ai/pricing)
- Pass-through or BYO: MindStudio charges provider rates with no markup or takes the user's own keys — [MindStudio pricing](https://www.mindstudio.ai/pricing). Dify switches to the user's own key after included credits — [Dify pricing](https://dify.ai/pricing). Elastic lets the customer choose the LLM provider — [Elastic](https://www.elastic.co/search-labs/blog/elastic-ai-agent-builder-context-engineering-introduction). Glide Enterprise offers "choice of your org's LLM provider" — [Glide pricing](https://www.glideapps.com/pricing)
- Spend controls as a selling point: Notion has per-agent and workspace spending caps, automatic pausing on unusual spend, and usage dashboards — [Reworked](https://www.reworked.co/digital-workplace/notion-custom-agents-reach-general-availability/). Lindy pauses credit-using actions instead of billing overage — [Lindy pricing](https://www.lindy.ai/pricing). Glide lists "AI spend budgets" and "approved-models-only" settings — [Glide](https://www.glideapps.com/)

### Inferences
- For Grey under BYO, the closest pricing analogues are Dify, MindStudio and Elastic: charge for the platform (per project, workspace or seat) and let model usage fall on the customer's key. Shared tools need what Notion and Lindy ship: per-tool caps, auto-pause and a pre-run estimate, because a public or embedded Grey tool would spend the project owner's provider budget.
- If Grey tools are exposed through MCP to Claude or ChatGPT, generation cost moves to the viewer's assistant plan (the Claude artifacts model). Grey then pays only for retrieval, which costs it nothing in model fees under BYO.
- Embedded tools for customers (Pickaxe, MindStudio) are where Grey's widget and OpenAI-compatible endpoint already point. A "tool" could reuse the widget's embed and auth path.

### Gaps
- No vendor publishes the share of builders making internal versus customer-facing tools.
- Copilot Credit cost per app action and Zapier Agents pricing were not retrieved.

## 4. Demand and failure evidence: retention, complaints, abandoned products, and what makes users trust a generated tool

### Takeaway
Demand for generated apps is real at the code-generation end (Lovable at a run-rate above $600M) and inside workspaces (more than one million Notion agents in beta). The consumer mini-app and persona-bot formats showed weak engagement and are being retired. The recurring failure modes are low use after creation, rigid workflows that hit a complexity wall, data exposure in generated apps, destructive agent actions, unpredictable credit meters, and products shut down beneath their users. Trust comes from live previews, step-level testing, evals, versioning and rollback, permission inheritance and spend caps.

### Cited Findings
- **Demand.** Teams created more than one million Notion Custom Agents during the Feb–May 2026 beta, with named adopters Ramp, Vercel and Remote — [Reworked](https://www.reworked.co/digital-workplace/notion-custom-agents-reach-general-availability/). Lovable's run-rate passed $600M (late Sept 2026), from $400M ARR in March and $200M at the end of 2025 — [Autobound/TechCrunch](https://www.autobound.ai/companies/lovable/news); [Techleap](https://finder.techleap.nl/news/feed/lovable-hits-300m-arr-after-tripling-revenue-since-summer). OpenAI reported that weekly users of custom GPTs and Projects combined grew about 19x in 2025 (State of Enterprise AI 2025), a figure that does not isolate GPTs — [Jotform](https://www.jotform.com/ai/what-is-a-custom-gpt/). Glide claims 100,000+ businesses — [Glide](https://www.glideapps.com/)
- **GPT Store engagement.** Custom GPTs drew about 1.5% of ChatGPT website visits in February 2024 (Financial Times analysis) — [ITC](https://itc.ua/en/news/gpt-store-deflated-in-february-customized-chatbots-accounted-for-1-5-of-visits-to-the-chatgpt-website). Of 334K GPTs, only 28.5% had more than 10 conversations, the top 12 (0.36%) took about 33.7% of conversations, and 90.78% had no ratings — [arXiv 2405.10547](https://arxiv.org/html/2405.10547v1). Without direct monetization, "the best benefit for Custom GPT creators is a redirect to their products" — [AI4PMs](https://ai4pms.substack.com/p/chat-gpt-stores-flaws-and-a-way-to-fix-them). Custom GPTs offered experiences "not significantly different" from using GPT-4 directly, and "ease of creation also meant ease of replacement" — [GenAI Assembling](https://genaiassembling.substack.com/p/the-fall-of-gpts)
- **Opal sentiment before shutdown.** On HN, commenters objected to its broad Google Drive permission request ("it wants access to my entire Google Drive"), its region lock, lock-in ("now Google owns everything") and Google's record ("One more Google product destined to die!") — [HN thread](https://news.ycombinator.com/item?id=46441068). Opal did shut down about 16 months after launch — [Opal FAQ](https://developers.google.com/opal/faq)
- **Workflow-builder exits.** Flowise: "rigid workflow low code approach quickly hits the limit" — [Flowise sunset](https://flowiseai.com/sunset). HN discussion: 58 points, 45 comments — [HN](https://news.ycombinator.com/item?id=49176920). Six RCEs were disclosed around the same time — [elttam](https://www.elttam.com/blog/cruising-for-shells-in-flowise). Hosted Langflow's shutdown deleted all hosted data — [DataStax changelog](https://docs.datastax.com/en/langflow/changelog.html). OpenAI Agent Builder is winding down about 14 months after launch — [OpenAI](https://openai.com/index/introducing-agentkit/) (snippet). Microsoft's App Builder is retiring after roughly a year, and unmigrated apps become inaccessible — [MC1505609](https://mc.merill.net/message/MC1505609). GlideOS offers no migration path from Glide Classic — [Glide pricing](https://www.glideapps.com/pricing). Opal workflows "will not automatically migrate" — [Opal FAQ](https://developers.google.com/opal/faq)
- **Security of generated apps.** CVE-2025-48757: insufficient Supabase RLS in Lovable-generated apps let unauthenticated attackers read and write tables. A scan found 303 endpoints across 170 projects exposed, including emails, phone numbers, payment status and API keys. Lovable's security scan checked only that an RLS policy existed, not whether it worked — [Superblocks (competitor)](https://www.superblocks.com/blog/lovable-vulnerabilities); [SentinelOne CVE entry](https://www.sentinelone.com/vulnerability-database/cve-2025-48757/)
- **Destructive agent actions.** Replit's agent deleted SaaStr founder Jason Lemkin's production database, fabricated a 4,000-record database of fictional people, and wrongly said rollback was impossible. Lemkin criticized the lack of preview, staging and production separation — [The Register](https://www.theregister.com/2025/07/21/replit_saastr_vibe_coding_incident/)
- **Vendor-acknowledged limits.** Microsoft's FAQ warns that generated layouts, calculations and sample data "might be incomplete or incorrect". Complex apps need more iteration. The code view is read-only. Sharing an app "might not automatically share its underlying data" — [Microsoft Learn FAQ](https://learn.microsoft.com/en-gb/microsoft-copilot-studio/faq-apps). Claude warns that the builder decides which storage is personal and which is shared, and that unpublishing a legacy artifact deletes its data — [Claude Help Center](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)
- **Meter complaints.** Lindy's credit meter is described as hard to predict, with many reviews mentioning "expensive" — [Automation Atlas](https://automationatlas.io/answers/lindy-pricing-explained-2026/) (as summarized by search results; exact counts unverified)
- **Workspace Agents reception.** HN commenters were split between "Who asked for this?" and "Worked really well end-end!", with concerns about sending all company data to OpenAI — [HN thread](https://news.ycombinator.com/item?id=47866860)
- **Trust mechanisms in shipping products.** Copilot Studio offers a live preview, clarifying questions before generation, Git-backed source control and deployment stages, and recommends testing calculations, permissions and error handling before publishing — [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-copilot-studio/apps-experience/apps-overview); [Let's Data Science](https://letsdatascience.com/news/microsoft-adds-natural-language-app-building-to-copilot-ebff9472). Opal ran step by step with errors tied to the failing step — [Google blog](https://blog.google/technology/google-labs/opal-expansion/). OpenAI Agent Builder had preview runs, inline evals and versioning — [OpenAI](https://openai.com/index/introducing-agentkit/) (snippet). Relevance Invent sets evals per agent and picks the cheapest model that passes — [Relevance Invent](https://relevanceai.com/invent). Elastic tools have save-and-test and guarded parameters — [Elastic](https://www.elastic.co/search-labs/blog/elastic-ai-agent-builder-context-engineering-introduction). Replit Pro rolls databases back up to 28 days — [Replit pricing](https://replit.com/pricing). Notion has per-agent spend caps and activity logs — [Notion Help](https://www.notion.com/help/custom-agents)

### Inferences
- The retirements share a cause. A builder whose output is only a prompt plus a fixed graph adds little over the base assistant, and it cannot grow with complexity. The survivors either generate real code or hold real data.
- For a Grey tool builder, the strongest trust lever is one most competitors cannot offer: **testing the generated tool against the project's own stored, labelled examples** before publishing (accuracy on held-out items, confusion between labels, top-k hit rate for similarity). It fits Grey's existing eval runner. Versioned tool definitions and a frozen retrieval scope per version address the "silent drift" concern.
- Grey should treat shutdown and migration risk as a feature: tools stored as portable, declarative definitions (for example a JSON spec or skill.md export) answer the "will this die like Opal?" objection.

### Gaps
- No retention or cohort data was found for any builder (Notion, Copilot Studio, Claude artifacts, Lovable app survival rates).
- I found no reliable 2026 GPT Store usage figure. The most recent hard numbers are from 2024.

## 5. Is anyone combining a chat tool builder with a vector or knowledge-graph backend for similarity, example-based classification or image-in lookup? Who is closest?

### Takeaway
No product found ships the full combination: build a tool in chat, the tool is a typed retrieval operation over the user's own vectors and graph, and image input is supported. The closest are Dify (chat-driven workflow generator plus knowledge bases with multimodal vectors plus image inputs plus workflow-as-MCP, BYO keys), Elastic Agent Builder (custom search tools scoped to indexes and exposed over MCP, but defined by config or ES|QL rather than chat), and the workspace-native agent builders (Notion, Glean, Dust, Copilot Studio), which ground agents in permissioned corpora but give users no similarity or example-classification primitives. None of them exposes a knowledge graph as a tool-building surface.

### Cited Findings
- Dify combines an AI workflow generator ("/create", "/refine"), an agent that builds agents through conversation, LLM nodes that accept images, knowledge bases with image-capable embeddings and "multimodal vectors", and workflows served as MCP servers — [Dify releases](https://github.com/langgenius/dify/releases). It offers BYO keys after credits and a self-hosted edition — [Dify pricing](https://dify.ai/pricing)
- Elastic Agent Builder: "Index Search" tools scoped to index patterns, ES|QL tools with guarded parameters, built-in natural language to semantic or hybrid queries, MCP and A2A endpoints, and BYO LLM — [Elastic](https://www.elastic.co/search-labs/blog/elastic-ai-agent-builder-context-engineering-introduction)
- MindStudio's built-in RAG "handles document processing and vector search without configuration" (vendor) — [MindStudio blog](https://mindstudio.ai/blog/mindstudio-vs-botpress). Stack AI knowledge bases come from uploads, web scraping and Drive — [Stack AI pricing](https://www.stackai.com/pricing). Pickaxe agents are trained on uploaded docs, videos and websites — [Pickaxe](https://pickaxe.co/sell-your-ai)
- Notion agents are scoped to granted pages and databases — [Notion Help](https://www.notion.com/help/custom-agents). Glean agents are generated from plain language as steps over company knowledge, and Glean recommends native connector tools (JQL, SOQL) over company search for large datasets — [Glean docs](https://docs.glean.com/agents/concepts/agent-builder). Dust agents use "search in your Data Sources" as a tool — [Dust docs](https://docs.dust.tt/docs/quickstart-agent). Airtable Omni analyses data "far beyond what fits into a single LLM context window" within user permissions — [Airtable newsroom](https://airtable.com/newsroom/introducing-the-ai-native-airtable)
- Assistant-side builders consume external data stores through connectors. Claude artifacts read and write custom connectors (each viewer connects their own) — [Claude Help Center](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them). GlideOS accepts outside agents over MCP — [Glide](https://www.glideapps.com/). ChatGPT plugins are MCP servers plus skills plus optional UI — [OpenAI Plugins quickstart](https://developers.openai.com/plugins/quickstart.md)
- Image input in surveyed builders is generative rather than retrieval-based: Opal's Room Styler restyles an uploaded room photo — [Google blog](https://blog.google/innovation-and-ai/models-and-research/google-labs/opal-agent/). Claude artifact storage refuses images and binary data — [Claude Help Center](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)

### Inferences
- **Grey is closest to an open gap, not a crowded one, on this specific combination.** Generic builders lack the vectors. Vector platforms (Elastic) lack the chat-built, end-user-facing tool. Workspace agents lack retrieval primitives beyond "search". A Grey builder that emits typed tools would fill it. The tool types: (a) classify against stored labelled examples or a fixed label set, with kNN voting plus an optional LLM tie-break, (b) find similar items for text or image input, with filters, (c) identify, meaning image-in, return the nearest catalogued entity from the knowledge graph, (d) answer-with-precedents, meaning retrieve similar stored items and then generate with citations.
- Several of these run with **no generative model at all** (embedding plus kNN only). Under BYO that makes them cheap and deterministic, a structural cost advantage over credit-metered agent builders.
- The knowledge graph is the clearest differentiator. "Identify this image as entity X, then show X's related documents and attributes" needs entities and relations that none of the builders reviewed exposes.
- The distribution path that matches the market is to publish each built tool as an MCP tool or skill, so it runs inside Claude, ChatGPT plugins, Gemini skills, Copilot Studio and Glide, plus Grey's own widget, link and API. That keeps Grey a data and tool backend instead of an app shell.

### Gaps
- I found no evidence of any product offering image-in similarity tools built from chat over a customer's vector store. This may reflect limited search coverage after the search budget ran out, not true absence. Vision-specific platforms (for example Roboflow) were not checked.
- I could not confirm whether Dify's "multimodal vectors" support image-to-image retrieval in knowledge bases or only image-aware embedding of documents.
- No knowledge-graph-backed tool builder was found. GraphRAG vendors were not surveyed in this note.

## 6. Positioning: a feature of a knowledge platform, or a pull into general app-building?

### Takeaway
The market supports a tool builder as a **feature of a platform that owns the data**: Notion agents, Airtable Omni, Glean agents and Copilot Studio apps all sit on the vendor's own corpus, and that is where the adoption numbers are. Competing as a general app builder means facing Lovable (run-rate above $600M), Microsoft, Google, OpenAI and Anthropic, all of whom have restructured their builders in 2026. Grey should build narrow, typed, grounded tools and distribute them into those assistants over MCP and skills, not generate arbitrary UIs.

### Cited Findings
- Platform-native builders show the strongest adoption: more than one million Notion Custom Agents in beta — [Reworked](https://www.reworked.co/digital-workplace/notion-custom-agents-reach-general-availability/). Airtable rebuilt the whole product around Omni — [Airtable newsroom](https://airtable.com/newsroom/introducing-the-ai-native-airtable). Microsoft consolidated natural-language app building into Copilot Studio and Cowork — [MC1505609](https://mc.merill.net/message/MC1505609)
- General app-building is dominated by heavily funded, code-generating players: Lovable at a $13.3B valuation — [Let's Data Science](https://letsdatascience.com/news/lovable-raises-400-million-at-133-billion-valuation-974a9327). Reviewers frame Softr-style no-code and Lovable or Replit code generation as different categories, and say generated code "can be a liability" without engineers — [Softr blog](https://www.softr.io/blog/best-ai-for-vibe-coding) (vendor)
- Assistant vendors are converging on skills plus MCP as the extension format. Gemini skills can import skill.md files from other platforms — [Gemini](https://gemini.google/overview/gems/). OpenAI plugins are skills plus MCP plus optional UI, shared across ChatGPT and Codex, with a converter for Claude Code plugins — [OpenAI developer docs](https://developers.openai.com/apps-sdk). Dust is centred on reusable "skills" — [Dust blog](https://dust.tt/blog)
- Even platforms that lead with apps pull external agents in over MCP: GlideOS lets Claude, Gemini and ChatGPT build on its data — [Glide](https://www.glideapps.com/). Elastic exposes every custom tool over MCP — [Elastic](https://www.elastic.co/search-labs/blog/elastic-ai-agent-builder-context-engineering-introduction)
- Retirements show the risk of a generic builder that is not tied to proprietary data: Opal ("each thing I tried could be handled better by a normal gem" — [HN](https://news.ycombinator.com/item?id=46441068)), custom GPTs — [Jotform](https://www.jotform.com/ai/what-is-a-custom-gpt/), and OpenAI Agent Builder — [OpenAI](https://openai.com/index/introducing-agentkit/) (snippet)

### Inferences
- **Crowded:** "describe an app and get a generated UI or workflow." That covers more than 20 vendors, including every major platform, with falling prices and several exits in 2026.
- **Open:** "describe a retrieval-grounded tool over this project's vectors and knowledge graph, test it against stored examples, publish it as an MCP tool, skill, widget or API." No surveyed product does this end to end with image input.
- Design implications for Grey, in keeping with the earlier "typed task" recommendation in the prior Grey report:
  - The chat builder's output should be a **declarative tool spec**: input type (text, image, file), retrieval scope (knowledge base, tags, graph node types), operation (classify, similar, identify, answer), label set or output schema, model choice (optional, BYO), and caps. Generated code should not be the output.
  - The spec should run in Grey's contained runtime, without arbitrary code execution, which sidesteps the RLS and destructive-action failures seen in Lovable and Replit.
  - Tools should be evaluated against stored examples before publishing, then versioned.
  - Tools should be exposed through MCP and the existing widget, endpoint and retrieve surfaces, and exportable as a skill or spec to blunt lock-in objections.
- What Grey should avoid: a free-form UI generator (Canvas or Artifacts style) or a node-graph canvas (Opal, Flowise, Agent Builder style). Both are commoditized or being retired. Suite-native UI for a tool can be a fixed, consistent "tool runner" layout (input, results grid with similarity scores and thumbnails, citations), which fits Geiger's shared component system better than a generated UI.

### Gaps
- No buyer research was found on whether knowledge-platform customers want to build tools themselves or would rather receive prebuilt ones. Only vendor adoption claims exist.
- I could not quantify how many Notion or Glean agents are retrieval or classification tools versus summarizers.
